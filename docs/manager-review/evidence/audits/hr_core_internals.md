# HR core internals audit (read-only, static)  paths relative to src/

## Confirmed findings (severity order)
1. HIGH terminated employee keeps access. modules/employees/employees.service.js:336 -> employees.repository.js:95 only sets Employee.employmentStatus/deletedAt. User.status stays ACTIVE, sessions not revoked, pending leave/regularization/timesheets not cancelled. middleware/authenticate.js:21-36 checks only session.revokedAt, never User.status/Employee.deletedAt. Scenario: HR deletes employee; they keep calling APIs on the 15m JWT, refresh for 7d, and can log in again.
2. HIGH no trustProxy. app.js:44 Fastify({logger}) has no trustProxy (grep: none anywhere). plugins/rateLimit.js:3-8 global 100/15min keyed on request.ip. Behind nginx/docker every user shares the proxy IP: 100 reqs/15min for the whole tenant base (self-DoS), and the 5/15min /auth/register and OTP limits become global. login, admin/login, refresh have no per-route limit and no per-account lockout (no failed-attempt counter found in auth.service.js).
3. HIGH leave team-scope bypass. modules/leave/leave.repository.js:328-333: if query `employeeId` is present the where is {tenantId, employeeId} and the managerId filter is skipped. Any MANAGER can GET /leave/team/requests?employeeId=<any employee in tenant> (getLeaveRequestsSchema accepts employeeId, leave.validator.js:18). Reads reason/dates/approver comments of peers/HR.
4. HIGH leave range DoS. leave.validator.js:3-11 only checks start<=end. leave.service.js:14-18 eachDayUTC loops per day (twice: holiday resolve + chargeable). Employee submits 0001-01-01..9999-12-31 -> ~3M iterations plus holiday resolver, blocks event loop; also preview endpoint. No back-date or max-length limit.
5. HIGH legacy balance math inconsistent. leave.service.js:196 available = balance - pending (ignores used); :476 available = balance - used - pending. Approve (:340-343) increments used but never reduces balance, so after approval, create-check regains the used days: employee with balance 5 can request 5, get approved, request 5 again, repeat. Only legacy (non-policy) types.
6. MED approvals non-atomic. leave.service.js:289-345 read status -> update -> ledger posts, no $transaction, no conditional update (status:'PENDING' in where). Two concurrent approves double-post LEAVE_TAKEN; approve vs withdraw race. Same for create (:206-247: balance check, overlap check, insert not in a tx; double-click creates overlapping requests). bulk approve (:55) sequential with per-id errors swallowed (message leaked).
7. MED HR self-approval. utils/approvalGuard.js:23 returns for HR_ADMIN/SUPER_ADMIN before the self-approval check (:27). HR can approve own leave/timesheet. attendance.service.js:309-317 isAdminScope also skips self check for regularization.
8. MED attendance back/forward-dating. attendance.validator.js:9 `date` accepts any YYYY-MM-DD; attendance.service.js:34 uses it for attendanceDate with real checkInAt. Employee can create PRESENT records for any past/future day (also affects payroll). Check-in is also creatable on approved-leave/holiday days (no checks).
9. MED geofence is fake. attendance.service.js:51-55 hardcoded office coords (28.5244,77.1855), 100m, for all tenants; result only returned (geofenceValid), never persisted or enforced; WFH not exempted. No overtime/shift model exists in attendance (only timesheet overtimeThresholdHours, schema.prisma:1740).
10. MED invitation reactivates disabled user. auth/invitation.service.js:241-244 sets User.status ACTIVE without checking prior status or Employee termination; a revoked/terminated user with an unused token is re-enabled. Token valid-until-expiry; no check that employee deletedAt is null.
11. MED refresh rotation race. auth.service.js:366-470: read session, compare hash, then revoke+create non-atomically; concurrent refresh (FE double-fire) both succeed or trips TOKEN_REUSE and kills whole family (logout storm).
12. MED timesheet approvals list unscoped. timesheets.repository.js:144-153 ignores _managerId; timesheets.service.js:359 -> any approver-role user sees every tenant timesheet (with entries), unpaginated. Approve/reject itself is guarded (service:321,338).
13. MED ops. ops/ops.routes.js:8-13 accepts OPS_LOGS_TOKEN in ?token= (logged in proxy/access logs) with non-constant-time compare; token grants log read with no user identity. notifications SSE (notifications.routes.js:80-99) accepts JWT in query string; sseClients.addClient (utils/sseClients.js:26) has no per-user connection cap.
14. LOW /auth/register open (auth.routes.js:11-36) creates tenant+SUPER_ADMIN; only protection is the (proxy-IP-keyed) 5/15min limit; schema password minLength 8 only; no email verification before tenant active; slug/key enumeration via 409.
15. LOW helmet CSP disabled (plugins/helmet.js); CORS is a static allow-list + credentials (ok). 
16. LOW updates by id only after separate tenant check (attendance.controller.js:448, employees.controller.js:427,528, timesheets.repository.js:156-170 submit/decide, employees.repository.js:95-98): safe today because callers pre-check tenantId, fragile (TOCTOU/no defence in depth).
17. LOW auditLogs/export repos mostly pass tenantId via a pre-built `where`; scan found no cross-tenant read. Tenant-less queries that remain are keyed by unguessable ids (auth sessions/otp/invitation tokens) or by design (notifications.deleteExpired).

## Workflow gaps
- Leave: no cancel-after-approval (CANCELLED status exists in enum/validator but no route/ledger reversal; only PENDING can be withdrawn); no manager-change handling (assertCanApprove uses current managerId, pending requests follow the new manager, old manager loses access, no reassign notify); terminated employee's pending requests stay PENDING; no back-dated rule; overlap check ignores half-day (no half-day field in createLeaveRequest); notifications are fire-and-forget (.catch(()=>{})), no audit-log write on approve/reject/withdraw in leave.service.js.
- Attendance regularization: submit (attendance.service.js:259) no duplicate/date-range/future check; approve only flips status to PRESENT, does not set check-in/out times; type silently dropped.
- Resignations/offboarding: no module (Resignation model only). Employee termination has no checklist, asset return, or access revocation.
- Webhooks: no src/modules/webhooks exists.

Indexes: AttendanceRecord has unique(tenant,emp,date) + tenant/date indexes (ok); did not review others.
