## CRITICAL
1. **helmet, CORS, global rate-limit are all inert** (plugins not wrapped in fastify-plugin). src/app.js:79-81, src/plugins/{helmet,cors,rateLimit}.js. Verified in-process: GET /health and /api/v1/x return NO security headers, NO access-control-*, NO x-ratelimit-*; 150 POSTs to a route with `rateLimit:{max:5}` all 200. Consequence: per-route limits on login/forgot/reset/verify-otp (auth.routes.js:32,170,239,278,299,343,374) never fire => unthrottled credential stuffing, reset spam, email bombing; only OTP per-challenge lockout (otp.service.js:157-169) protects. No account lockout on password failures (auth.service.js:40-61; LOCKED status only set manually). Fix: wrap with `fp()`.
2. **Live tokens committed to git**: `.mcp.json:10` (GitHub classic PAT, 40 chars, ghp_ prefix) and `.mcp.json:17`, `.codex/config.toml:9,29` (GitHub PAT + Render API key `rnd_`). Tracked, not gitignored; first added 615ded6 2026-07-22, still present (260f51b 2026-08-04). ROTATE both; purge history.
3. **Prod dependency CVEs, backend** (npm audit: 3 critical, 9 high): fastify (DoS, content-type body-validation bypass; direct), @fastify/jwt->fast-jwt (iss validation / crit header; critical but app verifies with `jose`, not fast-jwt, so low real exposure unless @fastify/jwt is used - grep shows jose in utils/token.js), @fastify/static + swagger-ui (auth-bypass/path traversal; /docs is public and served in prod), nodemailer (CRLF header injection; direct), sharp/libvips (direct; user-uploaded images pass through sharp -> exploitable via photo/doc upload), @fastify/busboy (multipart DoS; uploads authenticated), proxy-addr (transitive; irrelevant, Fastify has no trustProxy), tar/node-pre-gyp (build-time only), exceljs/uuid (export, low).
4. **Frontend prod CVEs**: next 16.2.6 has critical RCE advisories (Image Optimization API, next/og, Windows hosts) + high SSRF (rewrites, Image Opt, Server Actions) + middleware bypass -> upgrade Next. Vercel Linux/no rewrites reduces some, Image Optimization is on by default. `expr-eval` (critical code-exec + proto pollution) is a prod dep used in src/modules/payroll/utils/formula.utils.ts:1 to evaluate admin-authored payroll formulas in the browser => stored-XSS-grade risk if formula text is tenant-editable and shown to other admins; replace/sandbox. axios (many pollution/DoS), shadcn->mcp-sdk/hono/express chain is dev-tooling-in-prod-deps (move shadcn to devDependencies).

- PII by role: employee records returned via permission keys; payroll self-or-`employees:read-any` enforced in service (manifest notCovered). Verify salary/bank/national-ID field masking per role with a role-matrix test.
- Backups: Hostinger VPS snapshots only (provider-level); no encrypted, tested, off-site backup with retention policy documented; no PITR.
