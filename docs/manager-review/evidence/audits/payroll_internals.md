# EMS payroll internals audit (read-only; pure-function checks in scratchpad/deep/t.mjs)
Files: src/modules/payroll/payroll.{repository,service}.js, src/utils/{statutoryCalculation,money,payrollPeriod}.js

## Confirmed bugs (file:line, input)
1. BONUS/ARREARS run TDS always 0: payroll.repository.js ~L923 uses `periodEnd`, declared by `const` at ~L977 later in same function -> TDZ ReferenceError swallowed by `catch { bonusTax = 0 }`. Verified TDZ semantics. Also bonusNet uses Math.round(x*100)/100 and bonusTax Math.round (0dp) regardless of currency (KWD/JPY wrong).
2. Weekly/bi-weekly periods ("2024-W23"): `Number(run.period.slice(5,7))` = NaN (L~1062). lopFactor -> 1 (LOP ignored), payInPeriods never matches, monthIndex NaN -> TDS loop never runs -> zero income tax.
3. LOP on sub-monthly cycles: lopFactor = (calDaysInMonth - lop)/calDays applied to the H1 amount. 15 LOP days in H1 of June -> factor 0.5, should be 0 (verified).
4. Loan balance never decremented by payroll. Only L1304 reads balance; the only employeeLoan.update is manual (service L793). EMI recovered forever until endPeriod; schedule/"outstanding" never advance.
5. approveRunLevel (service L1665): no status guard - two POSTs levels 1+2 set status APPROVED from DRAFT/CALCULATING/CANCELLED/PAID; approver taken from body (`approvedBy||'SYSTEM'`, route even names it `approver`), same user can satisfy both levels, no initiator!=approver check. approvePayrollRun (repo L1370) has no maker-checker either, no check of calc warnings / missing employees.
6. updateRunPayslip (repo L1486): no run-status guard (edits PAID/APPROVED slips), not idempotent: adds whole one-time total onto gross/deductions on every PATCH, ignoring that calc already folded additions into net; run totals not updated; no audit event.
7. Concurrency: calculate checks DRAFT then updates (no atomic updateMany/CAS, no $transaction). Two simultaneous calculates both pass; both deleteMany + create -> P2002 on @@unique(runId,employeeId) is swallowed per-employee into warnings -> partial payslips, claims re-attached, run ends REVIEW with missing people. Any throw outside the per-employee try leaves run stuck CALCULATING (calculate only accepts DRAFT). Whole calculate is not transactional.
8. Overlapping salary rows (mid-period raise): query selects both rows; second payslip hits unique -> warning, order undefined; no split-period pay. No joining/leaving date proration at all (only LOP); employmentStatus !== 'ACTIVE' is skipped, so a terminated/exited employee is skipped even in an FNF run.
9. Statutory minor-unit table mismatch: statutoryCalculation.js CURRENCY_MINOR_UNITS lacks IQD, LYD (3dp) and UGX/XOF/XAF/PYG/RWF/etc (0dp) that money.js knows -> ceilings 10x/100x off (verified: IQD/LYD factor 100, UGX/XOF/PYG 100).
10. Tax/contribution rounding ignores currency: monthlyTax = Math.round (L~1237) -> KWD TDS whole dinars; contributions with no pack `rounding` use whole-unit Math.round (KWD EE 92.59 -> 93, verified). MONTHLY_TOTAL split floors to whole units: KWD semi-monthly 37 + 38.018.
11. Surcharge has no marginal relief; cliff verified (tax @5,000,000 = 1,500,000, @5,000,001 = 1,650,000). Rebate (87A-style) not expressible (taxCredits are flat). Cess/surcharge are fine otherwise.
12. Mixed-currency runs sum totalGross/Net/employerCost and PaymentBatch.totalAmount across currencies; run header currency = most common.
13. GL journal (service L2439): debit gross vs credit "Tax Payable"=ALL deductions (PF/loan/garnishment/TDS lumped) + net; one-time additions/reimbursements make credits != debits (net includes them, gross doesn't); employer contributions/employer cost never journaled; ignores SalaryComponent.glAccountCode/costCenterRule; `balanced` is float ===; CSV unescaped; no per-currency rounding.
14. markRunPaid flips ALL payslips to PAID incl. HELD ones (excluded from bank file); not atomic with run update; reimbursement claims settle only by runId (claims attached at calculate stay attached forever if run cancelled -> never paid; no release on cancel).
15. REVERSAL: no check target already reversed/is itself a reversal (double reversal allowed, YTD double-negates); lines negated w/o re-rounding; roundMoney(-2.5,'JPY') = -2 (asymmetric half-up).
16. Duplicate-run check (REGULAR only) is findFirst-then-create; no unique index -> race creates duplicates.
17. Statutory pack: update mutates in place (no versioning); legal-entity-pinned pack skips effectiveFrom/To check; recalc uses live pack, "pinned" meta is informational only. First taxRegimes[0] default.
18. Bank file: only NACH/ACH/SEPA/BACS flat CSV; no commas escaping; netPay<=0 not excluded; createPaymentBatch allowed repeatedly (no idempotency) and on PAID; reconcilePaymentBatch just flips status (no statement matching).

## Stubs / absent
- FNF run = ordinary calc for one employee; getRunFnf returns leaveEncashment:0, gratuity:0. Pack has `gratuity` config (UAE litmus 21d/30) but nothing computes it. No notice recovery, leave encashment, EOSB.
- getStatutoryReturn returns rows: [] (ECR/24Q/RTI stub). No Form 16 Part A/B (tax form = YTD totals template), no 24Q/26Q, no ESI computation beyond generic scheme, no PT beyond localTaxes slabs (monthly only, no Feb special).
- otHours collected in PayrollInput but never paid. variablePay only used by BONUS/ARREARS runs; regular run ignores it. No back-dated arrears calc (ARREARS = manually keyed amount). OpeningBalance not used in tax true-up (migrated mid-year joiners/ prior employer income ignored). TDS true-up is hypothetical (assumes constant salary, never reads actual YTD withheld; raise mid-year not trued-up; mid-year joiner assumes 12 months).
- Packs are DATA rows per tenant (StatutoryPack.packData: rounding, proration, taxRegimes, contributionSchemes, localTaxes, gratuity). No shipped packs in code; only scripts/globalCountryLitmusConfig.mjs (SA GOSI, AE, VN, SG, CA) + India seed (PF/PROF_TAX as components). No UK (PAYE/NI/RTI/P60), US (FICA/fed/state/W-2), EU, Kuwait PIFSS/EOSB, WPS SIF file (KW/UAE/KSA), Mudad. Bank formats lack WPS/SIF, SWIFT MT/pain.001, UK BACS Standard18.
- Approvals: no segregation, no thresholds; audit trail only for inputs/publish (payrollEvent) - approve/pay/cancel/edit write no event.
